# 记忆核心

一套给「每次会话都会被清空的 AI」用的记忆系统。

它要解决的不是「存下来」，是**下次醒来能接上上一次**——知道昨天发生过什么、自己当时为什么那样判断、对面那个人最近在为什么事烦。

## 最终形态（进行中）

目标只有一个：让对话历史不再占宿主窗口。

每轮原文落进本地 `turns`；窗口里已经不需要的旧段落被滚动替换成摘要（带 seq 范围 + 本地原文路径），最近 6 条原文永远不动。会话聊多长，窗口前端都不会跟着线性涨。

判据：

- 窗口里保留的原文条数有上界（最近 6 条），不随会话长度涨；
- 旧原文只从本地读；替换之后指代不断——「刚才那个」要能落在摘要或取回段上；
- 替换失败或库不可用，退回宿主原上下文，不静默丢历史。

边界：只管消息历史。工具结果、单轮超长输入、系统提示不经过这里，一条就能把窗口撑爆，这个插件不承诺兜住它们。

记忆按三个分区存放：`persona`（原则、偏好、说话方式，常驻）、`people`（谁是谁、关系、特征，提到时取回）、`tools`（本地工具、skill、路径，要做某类事时取回）。

替换现在只在白名单会话里真开（`~/.dsh/cache/replace-sessions.txt`），白名单外的会话不记账、也不动上下文。

## 为什么会有这个东西

对话的上下文有窗口，窗口满了要么压缩、要么换会话。换掉之后，模型对之前那一整段一无所知。历史文件还在磁盘上，但「在磁盘上」和「能想起来」是两件事：前者是存储问题，后者是检索问题，而检索的难点是**判断哪一段此刻相关**。

这套东西把那件事拆成可以分别验证的几块，而不是指望一个更大的上下文窗口。

## 怎么工作

```
session/event ──► turns（原文，只追加）
                     │  空闲 5 分钟
                     ▼
                refine() 提炼 ──► memories（信息点 + 摘要 + 锚点）
                     │
        agent/pre-step（每轮 step 1）
                     ▼
          retrieve() 三级取回 + 闸门 ──► 注入 1–2 条（≤600 字）
                     │
                     ▼
                recall_log（每条为什么被取回）

        session/event（assistant 回复后）
                     ▼
        planShadowV2() 滚动替换 ──► surfaceOp.replace（白名单内）
                     │
                     ▼
        shadow_v2（每轮一行：换了多少、断没断、真换没有）
```

三句话概括：

- **写原文，不写转述。** 模型（或规则）只产出摘要、类型、实体；正文由代码从原文截取，保证能回查。
- **取回必须能说出为什么。** 每条候选要写「这一轮缺什么、它补什么」；写不出就丢弃——那是相似度在替我做决定。
- **遗忘只降级，不删行。** 每条记忆带保留期：`permanent` 永不降级（preference 走这条）、`ephemeral` 7 天没碰就沉（情绪走这条）、`auto` 走默认曲线。每次降级记时间、原因、判据，账本可查。

取回不是往上下文里堆东西，是**换**：`pre-step` 把窗口里旧的对话消息换成取回片段，原文留在本地。

### 三级取回

| 级 | 来源 | 什么时候用 |
|---|---|---|
| L1 | 最近 3 条提炼（滑动窗口） | 锚点/实体对得上，就地解 |
| L2 | `memories` 信息点层 | 实体 + 锚点匹配，摘要能判断是否同一件事 |
| L3 | `turns` 原文层 | 前两层说不清，且句子带指代（之前/上次/那个/刚才） |

上限 2 条、合计 600 字。注入的消息带「不是当前指令」的外壳，不会被当成新的用户输入再收一遍。

### 影子账本

替换上下文是不可逆的，所以每轮先算「如果替换会删掉什么、补上什么」，写进 `shadow_v2`（换了哪段、原文多少字、摘要多少字、断链几条、真换没有）。白名单外的会话不记账、也不替换；白名单内的会话按滚动步长真换，账本照记。代价是没法先「只看不换」地观察一个会话再决定要不要放它进白名单——要不要放，得事先判断。

## 数据模型

SQLite，`node:sqlite`，无原生依赖。十张表：

| 表 | 存什么 |
|---|---|
| `turns` | 原文，只追加，唯一键 `(sid, seq, role)` |
| `memories` | 提炼后的信息点：类型、摘要、正文、锚点、实体、tier、保留期 |
| `entities` | 实体与出现次数，用于检索与去重 |
| `embeddings` | 向量（v0.2.0 起：1024 维本地向量，只作候选，不单独放行） |
| `runs` | 提炼/维护任务的执行记录 |
| `recall_log` | 每次取回：命中哪条、为什么、注入没有 |
| `shadow_log` | 旧影子账本（v0.2 之前的取回账） |
| `shadow_v2` | 滚动替换账本：换了哪段、省了多少字、断链几条、真换没有 |
| `forget_log` | 遗忘记录：哪条被降 tier、为什么 |
| `carry_log` | 跨会话接续记录：哪个来源会话、接到第几条、时间戳 |
| `forget_log` | 遗忘账本：tier 变化的时间、原因与保留期判据 |

## 边界：引擎进仓库，内容不进

- **引擎层**：代码、契约、表结构、测试、设计文档。在本仓库，可以公开。
- **内容层**：记忆分片、原话素材、审计日志、画像、日记。在 `~/.dsh/memory/`，**永远不进本仓库**，连测试用例都不用真实数据。

判据只有一句：这份文件删掉真实的人名、原话之后，测试或文档还成立吗？不成立就不进。

## 设计原则

1. **取回可验证。** 取回一段，只因为它补上了这一轮缺的一个信息点；说不出补了什么，就说明是相似度在替我决定。其余每一条都为它服务：契约管字段，锚点提供凭据，分层只管顺序。
2. **写原文，不写转述。** 摘要是我写的，我写时省掉的句子就真没了。
3. **遗忘必须有账。** 降级不删除；每次降级留时间、原因、判据。
4. **锚点要跨会话可回查。** 不用运行时会失效的编号（`mNNNNN` 那类），用落盘的事件序号。
5. **判断的关口交给人。** 素材→记忆、记忆→身份这两处不自动化；定时任务只做机械检查。
6. **首要目标不是省上下文，是「下次能想起来」。** 省 token 是副作用，不是目的。
7. **只标不删。** 检索排名可以降，原文不删。

## 安装

这是一个 DSH 插件（`plugin/dsh-cat-ill-remember-you`，名字 **I'll Remember You**）。

1. 在 profile 的 `dependencies` 里加 `dsh-cat-ill-remember-you`（指向本目录），并在 `dsh.profile.bundles` 里加同一条；
2. `pnpm install`；
3. 重启 dsh。

数据库默认在 `~/.dsh/memory/core.db`，可用 `DSH_MEMORY_CORE_DB` 覆盖。
