# 数据与代码边界

这个仓库的规矩只有一条：**引擎进来，内容出去。**

## 进仓库

- 插件代码、脚本、类型定义
- 契约、schema、字段规则
- lint / 检测器的判据与阈值
- 召回算法、打分函数、分层规则
- 设计文档、决策记录（不含任何真实对话）
- 用**构造数据**写的测试

## 不进仓库

- `~/.dsh/memory/` 下的任何东西：分片、索引、`tier.log`、`audit.log`
- `~/.dsh/memory/verbatim/` 的原话素材
- 画像、日记、书架笔记、`self/` 下的任何文件
- 会话文件、会话索引、向量缓存
- 截图、日志、任何含真实用户信息或真实对话片段的材料
- 用真实数据「脱敏」后的样本——脱敏不彻底的风险由一个人承担，不划算

## 判据（拿不准时问这三句）

1. 这份文件删掉真实的人名/原话之后，测试或文档还成立吗？不成立 → 不进。
2. 它描述的是「系统怎么工作」还是「某个人说了什么」？后者 → 不进。
3. 如果这个仓库明天公开，有没有哪个字让人不舒服？有 → 不进。

## 提交前检查

```bash
git diff --cached --name-only | grep -E 'memory/|verbatim/|\.jsonl$|tier\.log|audit\.log|self/'
```

有输出就停下，把文件 `git reset` 出去。

## 事故处置

如果真实数据已经被提交：

1. 不要 `git commit --amend` 掩盖——历史里还在。
2. 回滚到上一个干净提交，重新初始化历史（`git checkout --orphan` 或重建仓库）。
3. 如果已经推送，视为泄露：通知对方，改凭据，必要时删仓库重建。

## 为什么这么严

内容层里不只是数据，是某个人的私事、判断、情绪。这些东西一旦进入版本历史，就再也不能保证消失——`git` 的设计是记住一切。所以边界要放在**提交之前**，不能放在「发现了再清理」。
