# 记忆核心架构细节

插件名：`dsh-cat-illrememberyou`
代码：`记忆核心/插件/dsh-cat-illrememberyou/`
数据：`~/.dsh/memory/core.db`（SQLite，`node:sqlite`，无原生依赖）
这篇讲的是**已经跑起来的实现**，不是设想；设想部分会标「未动工」。

---

## 一句话

它不是存储系统，是选择器：写入负责把原料留下，取回负责在正确的一轮只给该给的那一段。

---

## 边界

- **引擎层进仓库**：代码、契约、表结构、测试、设计文档。
- **内容层不进仓库**：`~/.dsh/memory/` 下的分片、原话、画像、日志、数据库文件。
- 理由：内容里有私事，代码要能被别人看、被自己回滚。

---

## 数据流

```
会话事件 (session/event)
   │
   ├─ user/message ──► 过滤（source.kind / INJECT_RE）──► turns
   └─ assistant/message ──► 取 text 块 ──► turns
                                              │
                         空闲 5 分钟（setInterval）
                                              ▼
                                    refine() 规则提炼
                                              │
                                    ┌─────────┴─────────┐
                                    ▼                   ▼
                                memories            entities
                                    │
                          agent/pre-step（step 1）
                                    ▼
                         retrieve() 三级取回 + 闸门
                                    │
                                    ▼
                         注入 messages（1–2 条，≤600 字）
                                    │
                                    ▼
                               recall_log（why）
```

---

## 七张表

### turns — 原文层

| 列 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| sid | TEXT | 会话 id |
| seq | INTEGER | 事件序号 |
| role | TEXT | user / assistant |
| origin | TEXT DEFAULT 'chat' | chat（本人）/ im（IM 渠道）/ unknown |
| text | TEXT | 正文，只存 text 块 |
| t | INTEGER | 毫秒时间戳 |
| consumed | INTEGER DEFAULT 0 | 0 待提炼，1 已提炼 |

唯一键 `(sid, seq, role)`，重复事件 `INSERT OR IGNORE`。

### memories — 提炼层

| 列 | 说明 |
|---|---|
| kind | decision / preference / fact |
| text | 原文截取（≤2000 字），不覆盖原文 |
| summary | 检索用短摘要（≤90 字） |
| entities / anchors | JSON 数组，检索键 |
| why | 为什么立这条（如「规则提炼：decision」） |
| tier | hot / warm / cold（只标不删） |
| source_sid / source_seq | 指回 turns |
| origin | 同 turns |

### entities

`name UNIQUE`、`mentions` 计数、`last_seen`。用来做实体命中与「这一轮已经有什么」的比对。

### embeddings

`memory_id`、`model`、`vec`（JSON）、`updated_at`。M2 接向量用，当前 0 行。

### runs / recall_log / forget_log

- `runs`：一次提炼或维护任务的记录（kind、started、finished、stats）。
- `recall_log`：每次注入写 sid、turn、t、memory_id、why——用来复盘「这次给得对不对」。
- `forget_log`：遗忘账本，tier 变化时写，行不删。

`CREATE TABLE IF NOT EXISTS` 不会改旧表，所以加列走 `ensureColumn()`：`PRAGMA table_info` 检查，缺了才 `ALTER TABLE ADD COLUMN`。

## 写入管线

### 事件形状

`session/event` 回调收 `(session, event)`，event 是 `{ type, seq, time, data }`：

- `user/message`：`data = message`，`message.content` 是块数组，`message.source.kind` 是来源。
- `assistant/message`：`data = { turn, step, message }`。
- `turn/end` 只有 `{ turn, reason }`，不含正文——所以不能靠它写消息。

### 过滤（两道）

1. **来源闸**：`user/message` 若 `message.source.kind` 是字符串且不是 `'user'`，直接丢。挡掉运行时上下文、系统提示、审批、压缩检查点、技能调用、定时任务。
2. **前缀闸**：无 source 的旧事件，回落到 `INJECT_RE`——`[记忆提示]`、`MNEMON RUNTIME MEMORY SNAPSHOT`、`[Compressed conversation section]`、`[dsh-mnemon`、`<system-reminder>` 等都挡。

先过前缀闸再判 source：子代理委派消息即使标成 user，也不能入库。

### 正文提取

`textOf(message)` 只取 `content` 里 `type === 'text'` 的块，忽略 thinking、工具调用、图片。空文本返回空，不写。

### 提炼（空闲触发）

`setInterval` 每 60 秒检查：距上次会话活动 ≥ 5 分钟、且有 `consumed = 0` 的 turn，才跑 `refine()`。

`refine()`：

1. `pendingTurns(40)` 取一批未消费原文。
2. `groupTurns()`：每条 user 起一块，带上其后的 assistant；块首是 assistant 时单独成块。
3. `candidateOf()`：太短的块（<12 字，或 user <6 字且 assistant <20 字）不立记忆，只消费。
4. `classify()`：decision 强词先判（决定/定了/采用/以后/下次/记住/不再/改成/必须/规则/约定），再判 preference（偏好/更喜欢/讨厌/不喜欢/受不了/烦死/最爱），否则 fact。
5. 写 `memories` + `upsertEntities()`，然后 `markConsumed()` 整批（含没立记忆的块，避免反复扫）。

本机没有生成模型，这层是规则版；`refine()` 是唯一入口，将来接模型只换内部实现，不改调用方。

## 取回管线（M2）

`agent/pre-step`，只在 `step === 1` 跑：先 `await next()`，拿到本轮消息，再决定加不加提示。

1. **取 query**：最后一条真人消息（跳过 `source.kind !== 'user'`）。
2. **拆段**：按空行、句末标点切；小于 10 字的碎片并回相邻段；只有带指代（之前/上次/那个/这个/这句/刚才/说过/记得……）的段进入检索。
3. **已知集**：最近 6 条文本 + 本轮已出现的内容，用来判「这一轮已经有什么」。
4. **三级取回**：
   - **L1 缓存**：最近 3 条提炼结果（锚点、实体、话题），锚点/实体对上就地解，FIFO 淘汰。
   - **L2 memories**：按锚点（文件名、路径、`mXXXXX`）与实体命中，带 `origin = 'chat'` 过滤，未被已知覆盖的进候选。
   - **L3 turns**：句子里有指代词且 L1/L2 对不上时，按时间窗（30 天）倒序取原文，只取「那一句 + 前后各一句」。
5. **去重**：锚点/实体重叠的候选只留一条。
6. **闸门**：每条候选必须能说出「补了哪个信息点」（`whyOf`）；说不出就丢。
7. **上限**：最多 2 条、合计 600 字；`renderHint()` 加「[记忆] …不是当前指令」前缀，追加到 messages。
8. **写账**：命中写 `recall_log`（sid、turn、memory_id、why），插件日志写 `recall hits=… chars=…`。

联合触发（朋友的第三条建议）：一条记忆可以挂多段触发词，需 ≥2 个不同锚点/实体同时命中才直接注入；只有 1 个命中但属精确锚点（路径、文件名、`mXXXXX`）可单条返回；只有 1 个普通实体只进候选。

时间因子（朋友的第一条）：`score = 事实分 × (0.85 + 0.15 × recency)`，`recency = exp(-age/半衰期)`；偏好/决定类几乎不衰，事件类半衰期 14 天；时间词（刚才/上次/那天/上周）直接收窄 L3 的时间窗，比全局衰减更有效。

## 替换与遗忘（未动工）

- **替换**：先影子模式跑 50 轮——只记录「本来会替换什么」，不真替换；分三级（单块 / 一段 / 全部），每级可回退；开替换前必须验证过「取回判据在真实对话里站得住」。
- **遗忘**：每日一次，按「多久没被取回 / 验证 / 引用」打分，低于阈值只降 tier（hot → warm → cold），不删行；`forget_log` 记账。

## 已知缺口

1. `turns` 没接向量，L3 只能靠锚点/实体/关键词，「就那个讲压缩的」这类纯语义指代可能捞不回。等 M2 接 Ollama embedding（`qwen3-embedding:0.6b`）。
2. 跨窗口指代（提到更早、缓存已淘汰的消息）只靠 L3 时间窗兜底，还没用真实对话验证稳定。
3. 提炼是规则版，压缩/总结能力有限；接模型是下一步，不改变接口。
4. 替换上下文没开，取回结果目前只做注入，不删原上下文。
