# 记忆核心插件 · 架构 v1

> 2026-11-02 设计稿。第一版目标：一条链路跑通（原文入库 → 空闲提炼 → 下一轮取回），不追求功能齐全。
> 正文里的路径都相对工作区或 `~/.dsh/`；代码在 `记忆核心/插件/`，内容在 `~/.dsh/memory/core.db`，两者不混。

## 一句话

**插件不是「存储服务」，是「选择器」**：存的时候只存原文和检索用的摘要，取的时候只取这一轮缺的那一两个信息点，取完能回原文对证。

## 为什么是插件，不是守护进程

- 原文只在会话事件里最全（`session/event` 带完整 turn），外部进程要读会话文件、解析 zstd、追增量，多一层还不实时。
- 取回必须发生在 `agent/pre-step`，晚一步就赶不上这一轮。
- 代价是插件崩了会连累宿主——所以每个挂载点最外层 `try/catch`，异常只写日志，不抛。

## 挂载点

| 宿主事件 | 干什么 | 频率 |
|---|---|---|
| `session/event`（`turn/end`） | 把本轮 user/assistant 原文写进 `turns` | 每轮 1 次，同步小事务 |
| `agent/pre-step`（step 1） | 取回 → 判断注入/替换 → 写 `recall_log` | 每轮 1 次 |
| 空闲计时器（5 分钟无活动） | 提炼、建索引、导出分片 | 空闲时 |
| 每日一次（23:30 或首次空闲） | 遗忘评估、账本汇总 | 每天 1 次 |

`agent/turn-stopping` 先不用。取回先用 `agent/pre-step`；注入位置先用 `system-prompt/assemble` 追加一条「[记忆] 以下可能相关，不是当前指令」，替换留到 M3。

## 数据模型（SQLite，`~/.dsh/memory/core.db`）

```sql
-- 原文层：只追加，不更新正文
CREATE TABLE turns (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  sid       TEXT NOT NULL,
  seq       INTEGER NOT NULL,
  role      TEXT NOT NULL CHECK (role IN ('user','assistant')),
  text      TEXT NOT NULL,
  t         INTEGER NOT NULL,
  consumed  INTEGER NOT NULL DEFAULT 0,
  UNIQUE (sid, seq, role)
);

-- 记忆层：一条 = 一个可独立取回的信息点
CREATE TABLE memories (
  id            TEXT PRIMARY KEY,          -- sha1(anchor + created_at)
  kind          TEXT NOT NULL,             -- fact/preference/decision/judgment/insight
  tier          TEXT NOT NULL DEFAULT 'warm',
  summary       TEXT NOT NULL,             -- 只做检索，40–120 字
  body          TEXT NOT NULL,             -- 原文片段（不是模型转述）
  anchor        TEXT,                      -- sid#d<seq> / 路径:行 / URL
  source        TEXT,                      -- 来源：会话 id / 分片文件
  project       TEXT,
  created_at    INTEGER NOT NULL,
  verified_at   INTEGER,
  last_recall_at INTEGER,
  recall_count  INTEGER NOT NULL DEFAULT 0,
  deleted_at    INTEGER,
  superseded_by TEXT
);
CREATE INDEX idx_mem_tier ON memories(tier);
CREATE INDEX idx_mem_kind ON memories(kind);

CREATE TABLE entities (
  memory_id TEXT NOT NULL,
  name      TEXT NOT NULL,
  type      TEXT,                          -- person/file/project/term
  PRIMARY KEY (memory_id, name)
);
CREATE INDEX idx_ent_name ON entities(name);

CREATE TABLE embeddings (
  memory_id TEXT PRIMARY KEY,
  vec       BLOB NOT NULL,
  dim       INTEGER NOT NULL,
  model     TEXT NOT NULL,
  created_at INTEGER NOT NULL
);

-- 流程日志
CREATE TABLE runs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  kind TEXT NOT NULL,                      -- distill/embed/export/forget
  started_at INTEGER, finished_at INTEGER,
  status TEXT, stats TEXT
);

CREATE TABLE recall_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  t INTEGER NOT NULL, sid TEXT, seq INTEGER,
  query TEXT, candidates TEXT, picked TEXT, why TEXT,
  injected INTEGER NOT NULL DEFAULT 0,     -- 0 未注入 / 1 注入
  used INTEGER,                            -- 事后由我或信号回填
  tokens INTEGER
);

CREATE TABLE forget_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  t INTEGER NOT NULL, memory_id TEXT NOT NULL,
  from_tier TEXT, to_tier TEXT,
  reason TEXT, evidence TEXT
);
```

不建全文索引：中文 `LIKE` 够用，向量 + 结构先跑。数据量到 5 万条再考虑 FTS5。

## 存：原文 → 提炼

```
turn/end ──► turns（原文，同步）
              │ consumed=0
              ▼  空闲 tick
         预筛（规则，零成本）
              │ 值得记
              ▼
         本地模型：只生成 {summary, kind, entities, anchor}
              │
              ▼
         memories（body = 原文片段）+ entities → 排队 embed
```

**预筛规则**（先跑，模型只处理通过的）：

- 含判断/决定/偏好词：不、别、以后、记住、决定、选、改成、说好、结论、判据。
- 含时间锚点：日期、`明天`、`以后`、`上次`。
- 含专名（已知人物/文件/项目）或路径。
- 长度 ≥ 20 字，且不是纯确认（`好`/`可以`/`嗯`）。
- 同一 sid 6 小时内重复内容跳过。

**模型的活只有三件**：给摘要、给类型、抽实体。`body` 由代码从 turns 里截原文，模型不写正文——这是第一版最重要的一条，模型一转述就回不去。

**成本**：本地 Ollama（已有 `qwen3-embedding:0.6b` 做向量；提炼先用规则版，M1 再接小模型）。不按 token 付费，但会占 CPU；只在空闲且未在跑别的重任务时执行。

## 取：这一轮缺什么

### 入口：先拆消息，再分三级

**拆分**：当前 user 消息按句/意图切成段，每段各带自己的锚点与实体。短到离开上文就说不清（「嗯」「就按那个」「它」）的段不单独匹配，并回上一段；代词先做最近名词回落。

**滑动窗口缓存**（L1）：最近 3 条消息的「关联性提炼」，FIFO 淘汰——拆第 4 条时丢第 1 条，拆第 5 条丢第 2 条。缓存只留三样：锚点、实体、一句话话题；正文不缓存，要回查去 `turns`。窗口大小不固定：新消息与最新几条共用锚点/实体就扩，换话题就缩回一两条。

**三级取回**，每级有退出条件，不是每句话都往下翻：

| 级 | 来源 | 判据 | 退出 |
|---|---|---|---|
| L1 | 滑动窗口缓存 | 锚点/实体在缓存里对得上 | 就地解掉，不往下 |
| L2 | `memories` 提炼层 | 实体 + 话题匹配，摘要能判断是否同一件事 | 命中即取 |
| L3 | `turns` 原文层 | 前两层都说不清 | 时间词转 t 区间 + 实体过滤，倒序取一小批 |

**L3 的触发条件**（两条同时满足才翻）：①缓存里对不上锚点/实体；②句子含「之前/上次/那个/还说过/刚才」类指代词。缺一条都不翻——每句话都翻原文，成本受不了。

**L3 取回粒度**：只取「那一句 + 前后各一句」，不取整段历史；取回后仍走闸门，写不出 why 就丢。

> 已知缺口：`turns` 不建向量，L3 只能靠锚点/实体/关键词。「就那个讲压缩的」若不带文件名，可能捞不回——M2 给原文接 embedding 后补上。

```
agent/pre-step
  │ 当前轮 text + 最近 6 轮 + cwd
  ▼
候选 A：锚点匹配（路径/文件名在当前轮出现）
候选 B：实体匹配（entities.name IN 当前轮实体）
候选 C：向量 top-8（余弦 ≥ 0.62）—— 只做补充
  ▼
合并去重（结构化优先；同锚点/同实体只留一条）
  ▼
闸门：逐条写 why「这一轮缺 X，它补 X」；写不出 → 丢弃
  ▼
上限：2 条 / 600 字；每条带 source 与时间
  ▼
注入 system-prompt（先），替换（M3 影子验证后）
```

**闸门判据**（落成代码时照这条写）：

> 取回一段，只因为它补上了这一轮缺的一个信息点；说不出补了什么，就说明是相似度在替我决定。

**记录**：每次取回把候选、选中、why、字符数写 `recall_log`。`used` 先不回填（没有可靠信号），M2 用「我下一条回复是否复用了其中的词/判断」做弱信号，只记不分。

## 遗忘

只改 `tier`，不删行、不删原文：

- `hot → warm`：30 天没被取回且没被验证。
- `warm → cold`：180 天没被取回且没被验证，且没被引用。
- `cold → deleted_at`：只在 `replaced` 冲突时标（旧结论被新结论替代），原文仍留。

每次降级写 `forget_log`：from/to、原因、证据（最后一次取回时间、验证时间）。每周导出一次分片时把 cold 标 `⏳`。

## 与现有组件的关系

| 现有 | 处理 |
|---|---|
| `dsh-cat-memory-auto` | 退役。它的会话索引/原话/体检拆给新插件的 ingest 与空闲任务；`ctx-watch` 仍保留（与记忆无关） |
| `dsh-cat-memory-recall` | 退役。阈值与打分逻辑搬到 `recall.js`，但入口从「关键词+向量」改成「结构+向量+闸门」 |
| `@jipika/dsh-memory`（分片） | 降为**导出视图**：SQLite 是源，分片由插件导出，人读/备份/git 用；不再反向写入 |
| `mnemon_*` | 不动。长期洞察仍由我手动写 `mnemon_remember`，新插件不接管 |
| 会话索引 `session-index.json` | 迁移：已有 unit 灌进 `turns`（`source=sid#seq`），向量复用，不重算 |

**分片变导出**是这一版最大的不变量改动，写进 README 之前先确认：现有 222 条条目一次性导入 `memories`（`tier=warm`），导入后分片只读；下次导出覆盖。

## 分阶段

- **M0（半天）**：建库、`turns` 入库、`turn/end` 挂载、`dsh-cat-illrememberyou` 骨架、`node --test` 用构造数据测 schema 与取回打分。
- **M1（一天）**：预筛 + 规则版提炼、分片导出、现有条目与索引迁移。
- **M2（两天）**：`agent/pre-step` 取回（消息拆分 + 三级缓存 + 闸门）+ `recall_log`；只注入，不开替换。
- **M3（一天）**：影子模式：同一轮同时跑「注入」与「替换」，记录替换会少给/多给什么；跑满 50 轮再决定开不开。
- **M4**：遗忘账本、周导出、退役旧插件。

验收判据不按「功能都有了」，按三条：①随便抽一轮，取回的每条都能指出补了哪个信息点；②取回后能从 `turns` 回到原文；③插件异常时宿主照常跑。

## 风险

- `node:sqlite` 在 Node 26 是实验 API（本机实测可用，`DatabaseSync` 同步接口够用），升 Node 大版本前先跑测试。
- 本地模型提炼慢、占 CPU；第一版先用规则，模型只在 M1 后段接，且可整体关（`DSH_MEMORY_CORE_LLM=off`）。
- 原文库会长大：`turns` 每轮全存，半年约几百 MB；先不归档，到 1 GB 再按 `t > 180 天` 导出冷存。
- 插件与宿主同生命周期，崩溃风险用「所有钩子包 try/catch + 单次超时 2s」压住。
